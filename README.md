# Personal OS

**Personal OS** — персональная модульная система управления временем, учёбой, репетиторством и техническими проектами.

Цель — связать календарь, задачи, фактически потраченное время и результаты учёбы, репетиторства и ML/IT-проектов. Продуктивность оценивается по достигнутым результатам и продвижению к целям, а не только по часам или количеству закрытых задач.

## MVP
- Dashboard: план дня, приоритеты, дедлайны, таймер, быстрые действия и вечерний обзор.
- Задачи, оценки длительности, сроки и учёт фактического времени.
- Репетиторство: ученики, занятия, ДЗ, начисления, оплаты и задолженность.
- Учёба: предметы, лабораторные, контрольные и дедлайны.
- ML/IT-проекты: стадии, задачи, milestones, результаты и связи с GitHub.
- Google Calendar, GitHub и Telegram integrations.
- Дневная/недельная аналитика, приглашения и изоляция пользователей.
- PWA и офлайн-доступ к последнему кешированному плану.

Полноценный личный бюджет и импорт банковских выписок — после MVP. Учёт начислений и оплат за репетиторство входит в MVP.

## Быстрый старт
Требуются Docker Desktop и Docker Compose.

1. Скопируйте `.env.example` в `.env` и замените секреты.
2. Выполните `docker compose up --build`.
3. Web: http://localhost:5173; API: http://localhost:8000; Swagger: http://localhost:8000/docs; health: http://localhost:8000/api/v1/health.

Документация: [ТЗ](docs/SPEC.md), [архитектура](docs/ARCHITECTURE.md), [модель данных](docs/DATA_MODEL.md), [безопасность](docs/SECURITY.md), [roadmap](docs/ROADMAP.md), [локальная разработка](docs/DEVELOPMENT.md).

> **Статус: активная разработка, не production-ready.** В feature-ветках реализуются авторизация, CRUD API, таймер, интеграции, tutoring CRM, учёба/проекты и outcome-based аналитика. Перед использованием с реальными данными нужно дождаться зелёного CI, проверить весь сценарий миграций/восстановления резервной копии, OAuth-настройки и production-конфигурацию.

## Ветки
- `main` — стабильная интеграционная ветка.
- `feat/foundation` — ТЗ, архитектура, инфраструктура и скелет приложения.
- `feat/auth-security`
- `feat/tasks-time-tracking`
- `feat/calendar-planning`
- `feat/tutoring`
- `feat/studies-projects`
- `feat/integrations-analytics`

Правила: backend проверяет ownership каждого объекта; внешние изменения требуют подтверждения; план не равен факту; начисление не равно оплате; фоновые операции идемпотентны; не коммитить `.env` и реальные данные.
